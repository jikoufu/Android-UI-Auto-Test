# 需求分析

读取项目政策与已有需求，写入当前任务的 `requirement.md`。保留用户已经确定的目标与约束；仅对会改变交付范围的缺口提出问题。

记录预期行为、可观察的验收条件、必要输入和明确不在本次范围内的工作。区分用户要求、现有实现事实与待验证假设。引用代码或文档位置说明依据，不把计划能力写成现状。

已有任务时更新原文件；简单请求无需人为扩展文档规模。将需要设备、外部服务或人工信息的验收条件显式记录，供后续验证选择正确环境。
