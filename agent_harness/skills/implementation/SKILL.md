# 代码实现

读取当前任务需求、适用设计与项目政策，先定位现有实现和调用方。围绕验收条件完成最小完整变更，保留无关用户修改。

对适合 TDD 的变更，沿用已有先行测试和 Red 证据，确认失败对应目标行为后，用最小完整实现使测试通过。通过后只整理本次触及的代码，并复跑相关检查。仅在重复代码实现同一条规则且需要同步变更时合并，避免为了形式相似引入抽象。

更新受影响的调用方、配置和使用说明，避免通过第二份配置或隐藏兼容层掩盖迁移遗漏。底层操作、业务编排与接口层的归属以项目规则为准。

运行与变更相称的检查，并将命令、退出码、行为结果与未验证条件交给验证阶段。实现者自测不等于独立验证；缺少依赖时记录阻碍，不能伪造通过结果。
