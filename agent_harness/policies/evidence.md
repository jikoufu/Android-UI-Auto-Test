# 验证记录规则

`verification.json` 由 `schemas/protocol.py` 中的 `VerificationRecord` 定义。记录当前任务验证范围内的最终检查状态，失败过程与重试历史通过脱敏日志保留。

| 状态 | 含义 |
| --- | --- |
| `not_run` | 未执行任何检查，不能标记任务完成 |
| `passed` | 记录中的检查均执行成功；未覆盖范围仍应写入 limitations |
| `failed` | 至少一项检查已执行失败 |
| `blocked` | 尚未执行，必要环境或输入缺失 |
| `partial` | 已执行部分检查，仍有阻塞、跳过或未运行项目；必须说明 limitations |

每项检查记录命令、结果、退出码、摘要与证据引用。`not_run`、`blocked`、`skipped` 不得填成功退出码。截图和日志仅保存到项目运行产物目录，任务记录使用相对路径引用，不粘贴凭证或设备敏感信息。

`task.yaml` 的 `complete` 只允许与 `passed` 验证记录配合。先明确验收范围；不要删除未完成的验收条件来凑通过结果。确有剩余验收工作时任务保持 `active` 或 `blocked`。

离线校验只能检查记录的一致性，不能替代真实执行与人工审阅，也不能验证外部证据的真实性。
